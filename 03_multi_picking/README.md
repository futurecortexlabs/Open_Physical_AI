# #03 複数ワークの順次ピッキング

#02 は赤いキューブ **1個** をカメラで見つけて拾いました。#03 では **複数個をまとめて見つけ**、**1つずつ順番に**（＝順次）ピック＆プレースして、バラバラに置かれたワークを一列のスロットへ並べ替えます。

ロボットを動かす土台（Jacobian IK・8フェーズの状態機械）は **#01・#02 と同一**です。増えたのは次の3つ。

| 追加要素 | 何をするか |
|---|---|
| **ブロブ分割** | 赤マスクを連結成分に分けて、ワーク1個ずつの重心を取る |
| **タスクキュー** | 検出した全ワークを処理順に並べ、1個終わったら次の1個へ |
| **標準アセットのワーク** | 自作キューブをやめ、Isaac Sim 標準アセットを参照する |

## ワーク：Isaac Sim の標準アセット

#01・#02 は `UsdGeom.Cube` で赤いキューブを自作していました。#03 では **YCB の赤いスポンジブロック**（`/Isaac/Props/YCB/Axis_Aligned/061_foam_brick.usd`）を参照します。

| 項目 | 実測値 |
|---|---|
| サイズ | 77.9 × 51.2 × 52.6 mm（短辺 51.2 mm を 2F-85 の 85 mm 開きでつかむ） |
| 原点 | 中心（＝接地させる Z は高さの半分 0.0263 m） |
| 上面の色 | RGB 約 (130, 55, 52) / redness 約 75 → **#02 のしきい値のまま検出できる** |
| 物理 | **何も付いていない**（RigidBody も Collider も無い） |

物理が付いていないのがハマりどころです。参照しただけでは「見えるだけの飾り」なので、コード側で

```python
for descendant in Usd.PrimRange(prim):        # アセット内の全メッシュに
    if descendant.IsA(UsdGeom.Mesh):
        UsdPhysics.CollisionAPI.Apply(descendant)                 # 衝突形状
        UsdPhysics.MeshCollisionAPI.Apply(descendant) \
            .CreateApproximationAttr(UsdPhysics.Tokens.convexHull)  # 凸包で近似
UsdPhysics.RigidBodyAPI.Apply(prim)           # 剛体（落ちる・つかめる）
UsdPhysics.MassAPI.Apply(prim).CreateMassAttr(scene.work_mass)     # 質量
```

を自分で与えます（`MultiPickPlace._create_works`）。付け忘れると、つかんでも手をすり抜けます。

> ⚠️ **アセットは実行時にダウンロードされます。** `get_assets_root_path()` が返すサーバー（既定はクラウド）へアクセスできないと起動できません。オフラインで動かす場合は Isaac のローカルアセットパックを入れるか、`SceneConfig.work_asset` を手元の USD に差し替えてください。到達できない場合は分かりやすいエラーで停止します。
>
> 別のアセットに差し替えるときは、**上から見た面が赤いか**を必ず確認してください。実測では `Blocks/basic_block`（白・47 mm 角）、`Blocks/nvidia_cube`（緑・65 mm 角）、`Rubiks_Cube/rubiks_cube`（面ごとに色が違う）はいずれも赤検出に向きませんでした。赤以外を使いたい場合は `CameraConfig` のしきい値（`red_min` / `red_dominance`）を、その色用の判定に書き換える必要があります。

## 全体の流れ

```
サイクル頭 : ホーム姿勢へ戻して視界を確保 → 全ワークを検出 → 処理順に並べてキューへ
  ワーク 1 : 上空→下降→把持→持上→搬送→設置→解放→退避（8フェーズ）
  ワーク 2 : 同じ8フェーズ（★検出はやり直さない＝キューの次を処理するだけ）
  ワーク 3 : 同じ8フェーズ
全ワーク完了: ワーク側とスロット側を入れ替えて次サイクル（loop=True のとき）
```

検出は**サイクルの頭で1回だけ**です。腕が動いた後に撮り直すと、すでに並べ終えたキューブも「未処理のワーク」として見えてしまうため、**最初に全部数えてキューに固定する**方が素直で安定します。

## ブロブ分割のしくみ（マスク → 個体）

赤マスク自体は #02 と同じしきい値処理です（`R が高く、G・B より突出している`）。違いは、そのマスクを **ワーク1個ずつに切り分ける** ところ。OpenCV も scipy も使わず、numpy だけで完結させます（`label_blobs`）。

1. マスク内の全画素に「自分だけのユニークな番号」を配る
2. **4近傍の最大値を取り込む**、を変化がなくなるまで繰り返す
3. つながった画素はその塊で最大の番号に染まる → **1つの塊 = 1つのラベル**

```python
padded[1:-1, 1:-1] = labels                  # 外周を -1 で囲う（境界の場合分けを消す）
neighbor_max = np.maximum.reduce([
    padded[:-2, 1:-1], padded[2:, 1:-1],     # 上・下
    padded[1:-1, :-2], padded[1:-1, 2:],     # 左・右
])
updated = np.where(mask, np.maximum(labels, neighbor_max), -1)
```

番号は1回の反復で1画素ずつ広がるので、**反復回数はブロブの直径ぶん**。全画面で回すと無駄なので、赤画素を囲む矩形だけに切り出してから回します（矩形の外は全部背景なので、切り出しても連結関係は変わりません）。

ラベルが付いたら、ブロブごとに重心 `(u, v)` と深度 `d` を中央値で求め、#02 と同じ自前ピンホールモデルで世界座標へ逆投影します。小さすぎる塊（`min_pixels` 未満）はノイズとして捨て、残りを**大きい順**に `max_blobs` 個まで採用します。

## 処理順の決め方

「複数あるとき、どれから手を付けるか」はロボットの見せ場です。`ControlConfig.pick_order` で切り替えられます。

| 値 | 順序 |
|---|---|
| `"near"`（既定） | ロボット基準に近い順。手前から片付けるので腕の動きが小さい |
| `"far"` | 遠い順 |
| `"y"` | Y座標の昇順。見た目で追いやすい |
| その他 | 検出順（ブロブの大きい順）そのまま |

i 番目に拾ったワークは i 番目のスロットへ置きます（ワークは同一形状なので、どれがどこへ行くかは気にしません）。

## #02 からの差分

| 項目 | #02 | #03 |
|---|---|---|
| ワーク | 自作の赤いキューブ1個 | **Isaac 標準アセット（YCB スポンジブロック）を複数個（既定3個）** |
| 検出 | 赤マスクの重心1点 | **連結成分ごとの重心リスト** |
| 進行 | 8フェーズ →（往復） | **8フェーズ × キュー →（往復）** |
| 置き先 | 1点 | **一列のスロット（`slot_origin` + `slot_pitch` × i）** |
| IK・フェーズ定義 | \<同じ\> | \<同じ\> |

検出に失敗した場合（オクルージョン等）は #02 と同じく **既知の配置へフォールバック** して停止しません。検出数が置き先の数より多い場合は、置き先の数で頭打ちにします。

## 調整ポイント

| 設定 | 意味 |
|---|---|
| `SceneConfig.work_positions` | ワークの初期位置。**要素を増やせばワークも自動で増えます**（スロットも同数作られます）。Z は「アセット高さの半分」＝接地する高さ |
| `SceneConfig.slot_origin` / `slot_pitch` | 並べ直す先の起点と間隔 |
| `SceneConfig.work_asset` | ワークに使う標準アセットのパス。差し替える場合は `work_height` と各位置の Z、上面の色も合わせて確認 |
| `SceneConfig.work_mass` | ワークの質量（アセットに付いていないので自分で与える） |
| `ControlConfig.pick_order` | 処理順（`near` / `far` / `y` / その他） |
| `ControlConfig.loop` | `False` で全ワークを並べ終えたら停止 |
| `CameraConfig.position` | 見下ろしカメラの位置。**ワークとスロットの両方が画角に入る**ように置く |
| `CameraConfig.min_pixels` | これ未満のブロブはノイズとして捨てる |
| `CameraConfig.max_blobs` | 採用するブロブ数の上限（大きい順） |

### つまずきポイント

- **ワークが2個しか検出されない** → `debug: True` のログで `blob: px=...` の行数を確認。画角外に出ていないか（カメラを高くする／`position` を配置の中心へ）、ワーク同士が接触して1つの塊に見えていないか（`work_positions` を離す。既定は 0.14 m 以上離しています）、`min_pixels` が大きすぎないか。
- **2個が1個として検出される** → 隣接して塊がつながっています。配置を離すか、`resolution` を上げて隙間を解像させる。しきい値処理の性質上、**接触したワークは分離できません**（分離したいなら距離変換＋watershed などが必要）。
- **並べたワークを拾い直してしまう** → 検出はサイクル頭の1回だけの設計です。途中で再検出を挟むなら、既に置いたスロット周辺を検出対象から除外する処理も必要になります。
- **つかんでもすり抜ける／落ちない** → アセットに RigidBody・Collider を付け忘れていないか（標準アセットは物理が付いていないものが多い）。`_create_works` の凸包近似も確認。
- **アセットが読み込めず起動しない** → `get_assets_root_path()` がサーバーに到達できていません。ネットワークを確認するか、ローカルアセットパックを入れる、`work_asset` を手元の USD に差し替える。
- **ワークを増やしたら届かない／暴れる** → `work_positions` / `slot_*` を robot に近づける、`above_height` を下げる、`IKConfig.max_joint_delta` を小さくする。
- **検出に時間がかかる** → `label_blobs` は反復回数がブロブ直径に比例します（既定の配置で 1 回あたり 0.2 秒ほど）。サイクル頭の1回だけなので通常は問題になりませんが、気になるなら `resolution` を下げる。
- **ログが1行も出ない** → Isaac Sim（Kit）が先に root ロガーへハンドラを付けるため、`logging.basicConfig` は既存ハンドラを見て**何もしません**。さらに Kit 側は INFO を表示しないので `log.info` が消えます。#03 では自分のロガーに直接ハンドラを付け、`log.propagate = False` で Kit へ流さないようにしています（ファイル冒頭）。

> ⚠️ **カメラ API について**：本サンプルは `isaacsim.sensors.camera.Camera` を使っています。お使いの Isaac Sim のビルドで API 名やメソッドが異なる場合は、`WorkDetector.setup / initialize / detect` の3か所を調整してください（ここに検出処理は隔離してあります）。
