# 「右に20cm」を理解するロボットアームを、教師なしPPOで作ってみた

ロボットアームへ「右に20cm運んで」と伝えたら、決め打ちの軌道ではなく、学習済みの方策がピッキング全体を動かす。今回はNVIDIA Isaac Sim上で、その仕組みをPPOだけで作りました。

目標は、接近、把持、持ち上げ、搬送、配置、開放、退避を1つの方策で実行することです。人が途中で工程を切り替えたり、模範動作を与えたりはしません。最終的には物体の初期位置から全方向5〜30cmを、1モデルで90%以上成功させることを目指しました。

## 指示は目標座標へ変換する

実装は「右20cm」「左10cm」「奥15cm」「右15cm 奥10cm」のような限定された日本語を解析し、床面上の相対座標へ変換します。ロボット座標系のXYを直接渡すこともできます。

ここで重要なのは、指示ごとに別モデルを学習させないことです。方策の観測には物体から目標までの差が含まれるため、同じモデルへ異なる目標を渡せます。指示の解析は目標だけを変え、モデルの重み、報酬、成功条件には触れません。

## PPOが決める部分

PPOの行動は、手先のXYZ移動とグリッパー指令の4つです。同じ方策が30Hzで動き続け、ピッキングの最初から最後までを担当します。

一方、手先の移動を関節角へ変換するIK、下向き姿勢、関節制限、重力補償は低レベル制御として残しました。つまり「どちらへ動き、いつ開閉するか」はPPOですが、「その手先移動を安全な関節目標へ変換する部分」は従来制御です。物体や目標を見て動く工程制御は入れていません。

## いきなり全範囲では学べなかった

全方向5〜30cmと最大開始難易度を一度に与えると、成功経験がほとんど得られませんでした。そこで、すでに成功できる近距離・狭い角度から始め、各領域の成功率が基準を超えると距離と方向を少しずつ広げるカリキュラムを実装しました。

これは答えの行動を教える仕組みではありません。教師サンプルは0件で、PPOは報酬から試行錯誤します。カリキュラムが変えるのは訓練中の目標分布だけです。評価は常に全方向5〜30cm、最大開始難易度のままにしました。

## 約7時間半の結果

RTX 5070 Ti、RAM 64GBのPCで、256環境を並列化しました。30分の学習を12区間、各区間後に独立評価を行い、全体で約7時間29分かかりました。最終モデルは1,030更新です。

未使用4seed、16種類の指示、合計1,024試行で評価した結果は次の通りでした。

| 工程 | 成功率 |
|---|---:|
| 接近 | 45.31% |
| 持ち上げ | 25.78% |
| 搬送・目標到達 | 22.07% |
| 開放・退避 | 22.07% |
| 完了後2秒の維持 | **21.88%** |

目標の90%には届きませんでした。5〜10cmでは半数前後まで成功しましたが、20〜30cmと斜め方向が大きな課題です。訓練範囲も約5.6〜21.2cm、約220度まで広がったところで時間上限になりました。

PPOはロボット自身の試行経験を増やしながら方策を改善するため、適切なカリキュラムで学習を重ねるほど成功率の向上を目指せます。今回も終盤の全範囲評価は12.11%、14.75%、20.21%、21.88%と上向きました。一方で、PPOは更新するたび必ず良くなるわけではありません。成功率が一時的に下がることや停滞することもあるため、学習時間だけでなく未使用条件での評価をセットにすることが重要です。

## ここまでで分かったこと

指示された位置を目標として1つの方策へ渡す仕組みは作れました。PPOだけでも、狭い条件なら接近から配置後の安定まで一連の動作を獲得できます。一方、距離、方向、開始状態を同時に広げると、探索だけで90%へ到達するにはさらに多くの経験とカリキュラム設計が必要です。

次は学習範囲を全方向30cmまで広げ、遠距離ケースを重点的に経験させます。ただし評価分布は変更せず、全体・各seed・各指示のすべてで90%以上になった場合だけ合格とします。

ソースコード、公開モデル、全評価表、再現コマンドは[#04 README](../README.md)にまとめています。シミュレーション結果であり、実機へ適用する前には衝突、力、停止、異常系を含む別の安全設計が必要です。
